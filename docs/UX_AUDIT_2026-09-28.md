# LitReview UX Audit, 2026-09-28

This audit combines a line-by-line read of `frontend/src/` with screenshots of the live app at `:8001`. The screenshots cover dark and light themes at 1440×900, using runs wf-0001 (completed), wf-0002 (generating config) and wf-0003 (config ready). Paths are relative to `frontend/src/`.

Severity levels:
- **H**: blocks a task, misleads the user, or fails accessibility.
- **M**: adds friction or confusion.
- **L**: polish.

---

## 1. The seven systemic problems

These seven root causes account for about 80% of the findings. Fixing them clears most of the individual items in section 4.

| # | Root cause | Principle it violates | Better idiom |
|---|---|---|---|
| S1 | **The system hides its state.** A single "Discovery" spinner can cover a 40-minute run. `progress` and `startedTs` are computed but never rendered. A run blocked on the user shows no banner. | Norman, *gulf of evaluation*. Nielsen #1, *visibility of system status*. | A stepper with sub-status ("Screening · 212/480 · 6m"), plus a persistent **"Waiting on you"** banner with a CTA. |
| S2 | **Expensive and destructive actions have no safety net, while trivial ones get friction.** Double-tapping a circle re-runs paid phases. Archive fires instantly. "Approve screening" has no summary. Meanwhile users must pass a PROSPERO gate and a review-type quiz. | Shneiderman's golden rule, *permit easy reversal*. Raskin, *undo beats confirm*. Cooper, *excise*. | Toast with **Undo** for reversible actions. A **summary confirm** only for irreversible or paid actions. Remove gates that aren't needed. |
| S3 | **Developer language leaks into the product.** Examples: `PROG phase_2_search`, `SRCHOV MISS`, `rob=`, `pm2 status`, `Phase 6f Custom Diagram Drawing`, `secondary_review`, `Hidden mode (ops=1)`, "IEDO", "active learning". | Nielsen #2, *match the real world*. Krug, *don't make me think*. | Keep one `PHASE_LABELS` source with `short`/`long` fields and one humanize map. Move ops detail behind a "Technical details" disclosure. |
| S4 | **There is no real type scale, and too much text sits below the legibility floor.** 10–11px text appears 46 times. `text-muted` fails AA (3.67:1 on surface-1). The funnel strip is 11px monospace, and its most important number ("6 included") is cut off. | *Refactoring UI*: build hierarchy with weight and colour, not tiny size. WCAG 1.4.3. | Set an 11px floor (`--text-2xs`), use a 1.2 modular scale, and raise muted text to at least 4.5:1. |
| S5 | **Keyboard and focus are broken at the primitive level.** `Button` uses `focus-visible:outline-none`, which overrides the glass focus ring, so **no Button shows focus**. The app nests buttons inside buttons, uses hand-rolled menus with no Esc key, and has no focus trap in the mobile drawer. | WCAG 2.4.7, 2.4.11, 4.1.2. Tidwell, *keyboard-only operation*. | Use a 2px solid focus ring at full opacity. Use Radix DropdownMenu, Sheet and Tabs everywhere. Build cards with an overlay link and sibling actions. |
| S6 | **Data views hold data but don't help anyone think with it.** The table has no sort, no row detail and no export. Filters sit two popovers deep. The cost chart uses rainbow colours with redundant axes. Chart and table views sort differently. | Shneiderman's mantra: *overview first, zoom and filter, details on demand*. Tufte's *data-ink ratio*. Few, *Information Dashboard Design*. | Faceted filters with counts, sortable headers, an inspector drawer, a single-hue bar chart with direct labels, and one shared sort order. |
| S7 | **Visual weight doesn't match importance.** Five equal 230px tabs outweigh the content. Every sidebar card carries about eight data points. The primary user decision (screening approval) sits in a warning-styled button at the top of the list. The manuscript line length is about 150 characters. | Gestalt figure–ground. Hick's law. Butterick, *Practical Typography* (45–90 character measure). Cooper, *sovereign posture*. | Compact tabs (underline style), cards showing three facts, a sticky decision bar at the bottom, and a 68ch reading column with a TOC rail. |

## 2. Design toolkit: principles and idioms referenced

| Source | Concept used here |
|---|---|
| Don Norman, *The Design of Everyday Things* | Signifiers, feedback, mapping, constraints, gulfs of execution and evaluation |
| Jakob Nielsen, *10 Usability Heuristics* | Visibility of status (#1), real-world language (#2), user control and undo (#3), consistency (#4), error prevention (#5), recognition over recall (#6), accelerators (#7), minimalism (#8), error recovery (#9) |
| Steve Krug, *Don't Make Me Think* | Self-evident labels, eliminating question marks |
| Alan Cooper, *About Face* | Sovereign vs transient posture, *excise* (work that doesn't serve the goal), modeless feedback |
| Jenifer Tidwell, *Designing Interfaces* | Center Stage, Sortable Table, Inspector/Master-Detail, Wizard with escape hatch, Cancelability, Multi-level Undo, Jump to Item |
| Ben Shneiderman, *Designing the User Interface* | 8 golden rules (reversal, closure, internal locus of control). Visual-info mantra. |
| Jef Raskin, *The Humane Interface* | Undo over confirmation, habituation to dialogs |
| Edward Tufte, *Visual Display of Quantitative Information* | Data-ink ratio, chartjunk, direct labelling, small multiples |
| Stephen Few, *Information Dashboard Design* | Single-hue emphasis, contextual comparisons (per-unit cost) |
| Wathan & Schoger, *Refactoring UI* | Hierarchy via weight and colour, constrained spacing and type scales, fewer borders |
| Matthew Butterick, *Practical Typography* | 45–90 character line length, 120–145% line height |
| Lidwell et al., *Universal Principles of Design* | Hick's law, Fitts's law, progressive disclosure, 80/20 |
| WCAG 2.2 | 1.4.3 contrast, 1.4.11 non-text contrast, 2.4.7/2.4.11 focus, 2.5.8 target size, 4.1.2 name/role/value |

Proven product idioms used as references:
- **Rayyan / Covidence** triage: j/k navigation, i/e to include or exclude, inline decisions.
- **Linear**: compact list rows, Cmd-K command palette, toast with undo.
- **GitHub Actions**: step list with live sub-status and elapsed time.
- **Notion / Stripe Docs**: TOC rail with scroll-spy.
- **Airtable / Algolia**: faceted filters with counts.
- **Vercel**: grouped deploy log with severity filter and "jump to latest".

## 5. Recommended roadmap

**Sprint 1: Foundation (about 1 day, fixes about 25% of issues at once)**
1. Button focus ring, solid-fill contrast tokens, a lighter `--color-muted`, and light badge text tokens (section 4.9 High items).
2. Type floor of 11px, a `Button` size scale, and radius tokens.
3. One `PHASE_LABELS` source with short/long labels and one humanise map. Use them in the log, cost and stepper (S3).

**Sprint 2: Status and safety (S1, S2)**
4. Stepper sub-status and elapsed time, and a "Waiting on you" banner across tabs. Stop emitting an error event for `config_ready` (V1).
5. An explicit "Resume from…" menu with a cost-aware confirm. Undo toasts for archive, complete and restore.
6. Route runs to the tab that holds the next action (Config, Screening).

**Sprint 3: The screening gate (highest-value human task)**
7. A Rayyan-style triage list: inline I/E, j/k/i/e/u keys, bulk select, Exclude filter, confidence sort, and full abstract.
8. A sticky approval footer with a summary confirm, and separate approve and resume error states.

**Sprint 4: Data and cost thinking tools (S6)**
9. Papers: sortable headers, facets with counts, URL-synced filters, inspector drawer, CSV/RIS export, and the pager moved next to its table.
10. Cost: single-hue bars, per-included-study cost, one formatter, one sort.

**Sprint 5: Chrome and reading (S7)**
11. Underline tabs. Funnel strip reduced to "6 included of 1,716", with detail in a popover. Sidebar cards reduced to title, status and one metric. Completed runs auto-filed.
12. Manuscript: 68ch column, TOC rail with scroll-spy, figure-missing placeholders, a unified "Submission package" flow.
13. Setup: h1, question first, type cards plus "Help me decide", and "Start without registration".

**Guardrail:** add an ESLint rule banning `text-[Npx]`, `h-N` overrides on `Button`, and `outline-none` without a replacement ring. Add an axe-core pass to the vitest or Playwright regression checklist in `docs/UI.md`.
